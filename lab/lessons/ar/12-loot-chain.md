# ربط النتائج للوصول

نادرا ما تهم النتيجة الواحدة وحدها، فالتقييم الواقعي عن السلسلة حيث يقود تسريب صغير إلى وثيقة تقود إلى بيانات اعتماد تفتح بابا، ويمشي هذا الدرس سلسلة كاملة بما علّمتك إياه الدروس السابقة فقط، وهو في الوقت نفسه الطريق المرشد عبر عدة أعلام في المختبر.

## العقلية

كل نتيجة سؤال عن الخطوة التالية، فكلمة المرور الصريحة ليست الجائزة بل مفتاح يبحث عن قفل، والمسار المخفي ليس الجائزة بل خريطة إلى مكان حفظ المفاتيح، فتظل تسحب الخيط.

## امشِ السلسلة

ابدأ عند خدمة الويب واقرأ ما لا تقصد إظهاره.

```
curl -s http://127.0.0.1:8080/robots.txt
```

يسمّي ملف robots.txt مسارات يُراد لها أن تبقى خاصة وهذا بالضبط سبب قراءته، فاتبعها.

```
curl -s http://127.0.0.1:8080/admin-notes
curl -s http://127.0.0.1:8080/backup/config.bak
```

تذكر الملاحظات وحدة تحكم لم تُحكم قط، وتسرّب النسخة الاحتياطية أسرارا لا ينبغي أن تسكن جذر الويب أبدا، ثم استذكر الدرس الخامس حيث أرسلت صفحة الدخول القديمة كلمة مرور بنص صريح.

```
curl -s http://127.0.0.1:8080/login
```

تُعاد كلمة المرور نفسها على وحدة التحكم على المنفذ 2323، فإعادة الاستخدام هي كيف يصير التسريب الواحد ثلاثة، فاتصل وسجّل الدخول.

```
nc 127.0.0.1 2323
```

وحين تدخل تجوّل بالأوامر التي تعرضها.

```
HELP
HOSTNAME
USERS
LOGOUT
```

## لماذا يهتم المدافع

كثيرا ما يهمل المدافع نتيجة لأنها وحدها تبدو صغيرة، أما المهاجم فلا يفكر بنتائج مفردة بل بسلاسل، فكلمة مرور صريحة ونسخة احتياطية منسية وبيانات اعتماد معادة الاستخدام لا يقلق أي منها وحده لكنها مجتمعة تصير وصولا كاملا، فحين تصنّف النتائج اسأل عما تفتحه كل واحدة بعدها.

## جرّب بنفسك

اتبع الأثر إلى وحدة التحكم على المنفذ 2323 وسجّل الدخول ببيانات الاعتماد التي وجدتها بنص صريح ثم نفّذ HOSTNAME، وأرسل اسم المضيف الذي يطبعه، وفي الطريق ستمر بعدة أعلام فنفّذ netsec ctf كي ترى اللوحة.
