# الجدار الناري على المضيف

يقرر الجدار الناري أي الحزم يُسمح لها بالاقتراب من المضيف، وعلى لينكس تقوم النواة بالترشيح وأنت تشكّله بالقواعد، والأداتان هما nftables الحديثة وiptables الكلاسيكية التي ما زالت كثير من الأدلة تستخدمها.

## العقليتان

- يسمح **القبول الافتراضي** بمرور كل شيء إلا ما تحجبه، فهو سهل الكسر وسهل نسيان ثغرة فيه.
- يمنع **المنع الافتراضي** كل شيء إلا ما تسمح به، فهو الأساس الأكثر أمانا لأن خدمة نسيتها تبقى مغلقة لا مفتوحة.

يضبط الوضع الأكثر أمانا سياسة الإدخال على الإسقاط ثم يضيف قواعد ضيّقة للأشياء القليلة التي يجب أن تكون قابلة للوصول.

## قراءة القواعد بـ iptables

```
sudo iptables -L -n -v
sudo iptables -L INPUT -n -v --line-numbers
```

- يعرض `-L` القواعد، ويبقي `-n` العناوين أرقاما، ويظهر `-v` العدّادات.
- لكل سلسلة **سياسة** وهي الإجراء المستخدم حين لا تطابق أي قاعدة.

## رسم لمنع افتراضي

لا تحبس نفسك خارجا، وفي هذا المختبر أبقِ SSH مسموحا.

```
sudo iptables -A INPUT -i lo -j ACCEPT
sudo iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT
sudo iptables -P INPUT DROP
```

والفكرة نفسها في nftables أنظف.

```
sudo nft list ruleset
```

## لماذا يهتم المدافع

أكثر الانكشاف خدمة لم تكن بحاجة إلى أن تكون قابلة للوصول، فسياسة المنع الافتراضي تحوّل ذلك من خطر حي إلى باب مغلق، ثم إن قواعد الجدار الناري دليل مقروء على النيّة لذا يقرؤها المدقّق كي يرى ما يُفترض أن يقبله المضيف.

## جرّب بنفسك

اعرض القواعد الحالية بـ iptables واعثر على السياسة على سلسلة الإدخال، ثم أجب عن التحدي بالإجراء الذي يستخدمه الجدار الناري ذو المنع الافتراضي حين لا تطابق أي قاعدة.
