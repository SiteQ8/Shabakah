# استطلاع HTTP وخطر النص الصريح

يرسل HTTP بلا TLS كل شيء كنص قابل للقراءة وهذا يجعله معلّما مثاليا، فأي شيء يقوله العميل والخادم لبعضهما يستطيع قراءته أي أحد على المسار.

## قراءة خدمة HTTP

```
curl -s http://127.0.0.1:8080/
curl -sI http://127.0.0.1:8080/
curl -s http://127.0.0.1:8080/login
```

- الخيار `-s` صامت بلا شريط تقدّم.
- الخيار `-I` يطلب الترويسات فقط.
- الخيار `-v` يعرض التبادل الكامل من طلب ورد وهو أنفع عرض حين تتعلم.

```
curl -v http://127.0.0.1:8080/login
```

## مغزى الدرس

يشغّل المختبر صفحة دخول مهمِلة عن قصد، فهي تنقل اسم مستخدم وكلمة مرور كنص صريح، فإذا جلبتها وجدت السر أمامك في الجسم، ثم التقط الطلب نفسه على السلك وسترى أن مسار الشبكة يراه أيضا.

```
sudo tcpdump -i lo -n -A port 8080
```

ثم في طرفية أخرى اطلب الصفحة وراقب الالتقاط.

```
curl -s http://127.0.0.1:8080/login >/dev/null
```

## لماذا يهتم المدافع

هذه هي أوضح حجة على وجوب استخدام TLS في كل مكان، فبيانات الاعتماد والرموز وملفات الجلسة والبيانات الشخصية كلها تسافر مكشوفة على HTTP العادي، وعلى شبكة مشتركة يكون ذلك هدية لأي ملتقط للحركة، ثم إن نقل أي شيء حساس بنص صريح يعد ملاحظة أمنية قائمة بذاتها حين تدقّق نظاما.

## جرّب بنفسك

اعثر على كلمة المرور التي تسرّبها صفحة الدخول إما من جسم الاستجابة وإما من التقاطك، ثم قارن بالدرس التالي حيث يحمي TLS النوع نفسه من الخدمة.
