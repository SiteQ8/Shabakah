# استطلاع خدمات HTTP ومخاطر النص الصريح

يرسل بروتوكول HTTP غير المحمي بـ TLS كل شيء نصا مقروءا، وهذا ما يجعله مثالا تعليميا ممتازا، لأنّ أي طرف يقع على مسار الاتصال يستطيع أن يقرأ كل ما يتبادله العميل والخادم.

## استكشاف خدمة HTTP

```
curl -s http://127.0.0.1:8080/
curl -sI http://127.0.0.1:8080/
curl -s http://127.0.0.1:8080/login
```

- يشغّل الخيار `-s` الأداة بصمت، فلا يظهر مؤشر التقدّم.
- يطلب الخيار `-I` الترويسات وحدها دون محتوى الصفحة.
- يعرض الخيار `-v` التبادل كاملا بين الطرفين، أي الطلب والاستجابة، وهو أنفع ما تستعين به وأنت تتعلم.

```
curl -v http://127.0.0.1:8080/login
```

## الغاية من الدرس

يشغّل المختبر عن قصد صفحة دخول أُهمل تأمينها، فهي ترسل اسم المستخدم وكلمة المرور نصا صريحا، ويكفي أن تطلب الصفحة لتجد السر ظاهرا في محتوى الاستجابة، ثم التقط الطلب نفسه أثناء مروره على الشبكة لترى أن كل من يقع على مسار الاتصال يستطيع رؤيته أيضا.

```
sudo tcpdump -i lo -n -A port 8080
```

ثم اطلب الصفحة من طرفية أخرى، وراقب ما يظهر في الالتقاط.

```
curl -s http://127.0.0.1:8080/login >/dev/null
```

## لماذا يهمّ هذا المدافع

يقدّم هذا المثال أوضح دليل على ضرورة استخدام TLS في كل اتصال، فبيانات الاعتماد ورموز الوصول وملفات تعريف الارتباط الخاصة بالجلسات والبيانات الشخصية كلها تنتقل مكشوفة عبر HTTP العادي، وفي الشبكات المشتركة يصبح ذلك صيدا سهلا لكل من يلتقط الحركة، وعند تدقيق أي نظام يُعد نقل البيانات الحساسة بنص صريح ملاحظة تدقيق قائمة بذاتها.

## جرّب بنفسك

استخرج كلمة المرور التي تسرّبها صفحة الدخول، إما من محتوى الاستجابة وإما من الحزم التي التقطتها، ثم قارن ذلك بدرس TLS القادم، حيث تعمل خدمة من النوع نفسه محمية بـ TLS.
