# قراءة حركة الشبكة باستخدام tcpdump

إذا استطعت قراءة الحزم أجبت عن أسئلة لا تجيب عنها السجلات، فأداة tcpdump موجودة على كل جهاز تقريبا لذا يستحق إتقانها.

## شكل الأمر

```
sudo tcpdump -i <interface> -n <filter>
```

- يلتقط `-i lo` على واجهة الاسترجاع حيث تعيش أهدافنا المحلية، واستخدم `-i any` لمراقبة كل الواجهات.
- يمنع `-n` الأداة من تحويل العناوين والمنافذ إلى أسماء وهذا يبقي المخرجات دقيقة وسريعة.
- **المرشّح** في نهاية الأمر هو تعبير BPF وهو الذي يقرر ما تحتفظ به.

## خيارات مفيدة

- يطبع `-A` حمولات الحزم كنص وهذا مثالي للبروتوكولات غير المشفّرة.
- يطبع `-x` بالنظام الست عشري، ويطبع `-X` الست عشري والنص جنبا إلى جنب.
- يوقف `-c 20` الالتقاط بعد عشرين حزمة.
- يكتب `-w capture.pcap` الحزم الخام إلى ملف، ويقرأها `-r capture.pcap` لاحقا.

## مرشّحات ستعيد استخدامها

```
sudo tcpdump -i lo -n port 8080
sudo tcpdump -i lo -n tcp and port 8080
sudo tcpdump -i lo -n host 127.0.0.1 and port 8443
sudo tcpdump -i lo -n -A port 8080
```

## لماذا يهتم المدافع

الالتقاط هو وسيلتك لتأكيد ما غادر الجهاز فعلا لا ما تمنيت أن يغادر، وهو طريقك إلى اكتشاف بيانات الاعتماد غير المشفّرة والوجهات الغريبة والإشارات المتكررة، ثم إن ملف pcap المحفوظ دليل يمكنك تسليمه لغيرك وإعادة تشغيله.

## جرّب بنفسك

افتح طرفيتين إلى المختبر، وفي الأولى ابدأ التقاطا مع إظهار الحمولات.

```
sudo tcpdump -i lo -n -A port 8080
```

وفي الثانية أرسل طلبا كي يكون هناك ما تراه.

```
curl -s http://127.0.0.1:8080/ >/dev/null
```

راقب الطرفية الأولى، فسترى سطر الطلب ثم رد الخادم مع ترويساته، وإحدى ترويسات الاستجابة اسمها X-Lab-Token فاقرأ قيمتها.

> تظهر القيمة نفسها بالأمر `curl -sI http://127.0.0.1:8080` لكن هدف الدرس أن تراها على السلك لا في العميل فقط.
