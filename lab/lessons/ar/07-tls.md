# بروتوكول TLS والشهادات

بروتوكول TLS هو ما يحوّل HTTP الصريح إلى HTTPS، فهو يمنحك التشفير أثناء النقل والسلامة ووسيلة للتأكد من أنك تتحدث مع من تظن، والشهادة هي قلب هذا الجزء الأخير.

## ما تدّعيه الشهادة

تربط الشهادة مفتاحا عاما بهوية، وأكثر ما تفحصه هو **الجهة** أي لمن هي بما فيها الاسم الشائع والأسماء البديلة، ثم **جهة الإصدار** أي من ضمنها، ثم **تواريخ الصلاحية**، فالشهادة الموقّعة ذاتيا كالتي في هذا المختبر تضمن نفسها بنفسها لذا لا يستطيع العميل الوثوق بها تلقائيا.

## الفحص باستخدام openssl

اتصل وشاهد المصافحة والسلسلة.

```
echo | openssl s_client -connect 127.0.0.1:8443
```

استخرج الجهة وجهة الإصدار والتواريخ فقط.

```
echo | openssl s_client -connect 127.0.0.1:8443 2>/dev/null \
  | openssl x509 -noout -subject -issuer -dates
```

اعرض الشهادة كاملة بصيغة مقروءة.

```
echo | openssl s_client -connect 127.0.0.1:8443 2>/dev/null \
  | openssl x509 -noout -text
```

تحقق من إصدارات البروتوكول والشيفرات المتاحة.

```
openssl s_client -connect 127.0.0.1:8443 -tls1_2 </dev/null 2>/dev/null | head
nmap --script ssl-enum-ciphers -p 8443 127.0.0.1
```

## لماذا يهتم المدافع

يعد TLS الضعيف ملاحظة شائعة، فالشهادات المنتهية تكسر الثقة والتدريب، وإصدارات البروتوكول القديمة والشيفرات الضعيفة يمكن مهاجمتها، ثم إن شهادة لا يطابق اسمها المضيف الذي تخدمه إما خطأ وإما إنذار، وقراءة الشهادات يدويا هي طريقك إلى التحقق مما أبلغ عنه الماسح.

## جرّب بنفسك

اتصل بالمنفذ 8443 واقرأ جهة الشهادة ولاحظ الاسم الشائع، ثم قارن جهة الإصدار بالجهة وأكّد لنفسك أن هذه شهادة موقّعة ذاتيا وهذا بالضبط سبب اعتراض متصفحك عليها.
